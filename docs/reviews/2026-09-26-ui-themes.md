# Mafia UI review and room themes — 2026-09-26

## Decision and scope

Tanner chose one host-selected look for the whole room and the same controls in every theme. Built Noir Atelier (default), Midnight Club, and Neon Rain. The prior Case File design remains the noir foundation; this change adds three CSS art directions, clearer host/player reading order, and public authoritative theme state. House rules, six roles, silent/no-chat play, decoy actions, role projections, and one-time assignment reveal were not changed.

## Current browser/platform choices

- [MDN View Transitions](https://developer.mozilla.org/en-US/docs/Web/API/Document/startViewTransition) are available in current browsers but need a fallback. The current phase transition remains a small, interruptible CSS fade so a newer authoritative snapshot is never queued behind an animation.
- [MDN container queries](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Container_size_and_style_queries) can help future reusable host panels, but this change uses ordinary responsive CSS because the screens are already viewport-scoped.
- [MDN `color-mix()`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/color_value/color-mix) powers a few subtle surfaces; core text and background colors have explicit values.
- [MDN reduced motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/%40media/prefers-reduced-motion) drives the no-motion fallback. No WebGL or animated canvas is used on phones.
- [Jackbox's phone-controller accessibility notes](https://www.jackboxgames.com/blog/accessibility-features-in-the-jackbox-party-pack-10) informed the focus on obvious phone controls and per-device motion preferences; this app keeps one room-wide look by owner choice.

## Short human playtest

1. Give a first-time host a phone. Ask them to create a room and invite three to five players by QR, link, and code without coaching. Ask which step is next after each action.
2. Let the host choose a look and explain how it reaches every phone. Ask each player to find their seat, the rules, and what they expect when Start is tapped.
3. Play one full round in a dim room. Observe whether players keep their roles private, can find the night choice and lock confirmation, and know when to talk, wait, or vote.
4. Force one delay: lock a phone, reconnect it, and ask the host what the board says to do. Finish the vote, view the result and dead view, then rematch in a second theme.
5. Ask: “What did you think would happen next?”, “Did any screen make you unsure whether your choice counted?”, “Did another phone reveal information?”, “Which theme helped you read fastest and which made the table feel most tense?”, and “Would you choose to play again?”

## Remaining decisions and risks

- Human playtests must decide whether the three looks feel genuinely fun at a real table. A browser screenshot cannot establish that.
- Check QR scanning on older, low-brightness phones at typical table distance; the smaller 104px tile is a readability/space tradeoff.
- Test VoiceOver/TalkBack with real devices, especially the role-reveal dialog and night drawer. Automated accessible names/focus checks do not substitute for that.
- The visual theme is intentionally lobby-only; changing it mid-round would surprise players and is not implemented.
- One keyboard role-peek E2E run intermittently saw an empty live announcement after the timed reveal; four subsequent runs passed. Its cause is not yet reproduced.
- Production has not been changed by this UI work.

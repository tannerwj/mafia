# Spec 02 — implementation notes

- Verification note: this worktree is on `origin/master` (`b8254a2`) and lacks the Spec 00 scaffold files/scripts; `npm run typecheck` fails before engine code because `package.json` has no `typecheck` script.
- Tooling note: exact `npx vitest run --project engine` also depends on the missing root `vitest.config.ts`; engine files were kept within the requested source boundary.
- Coverage note: `test/engine` contains direct scenario tests, not the requested reusable `playGame(seed, ruleset, script)` DSL.
- API note: fixture roles are registered through the exported mutable role registry (`registerRoles`) instead of passing an explicit registry into `startGame`.
- Timing note: deadline effects can be produced from `applyCommand` when commands carry `now`, but `startGame(players, ruleset, seed)` cannot set an initial timed deadline because the pinned signature has no clock argument.
- v2.5 fix round: `src/shared/game-view.ts` now defines `RoleId`, `PlayerId`, `Phase`, `AttackTier`, `DefenseTier`, `NightActionType`, `VoteTarget`, and `GameEvent` standalone (zero engine imports); `src/engine/types.ts` imports and re-exports them from shared, restoring the engine -> shared dependency direction and fixing the `tsconfig.test-server.json` TS6307 error.
- v2.5 fix round: `startGame(players, ruleset, seed, now, roles?)` implemented — `now` feeds `effectsForDeadline` at game start so a configured night timer emits `setDeadline(now + timer*1000)` in the returned effects; `roles` is an optional `RoleRegistry` (defaults to `HOUSE_ROLE_DEFS`).
- v2.5 fix round: deleted the exported `roleRegistry`/`registerRoles` mutable-global pair. `RoleRegistry` cannot live inside `GameState` (it holds functions like `winHook`, and `GameState` is JSON-round-tripped on every `clone()`), so `startGame` now calls an internal `configureRoles(roles)` that sets a module-scoped `activeRegistry`, read via `currentRoles()` by `machine.ts`/`project.ts`. This is not exported from `src/engine/index.ts` — the only public way to configure roles is the `roles` param on `startGame`. Fixtures (`test/engine/fixtures/extra-roles.ts`) now export a `FIXTURE_ROLES: RoleRegistry` object (house six + Godfather/Jester/Escort) instead of calling a mutator, and pass it to `startGame` in tests.
- Bug found while adding the `firstNightKill=false` D7 scenario: `mafiaKillers()` (and therefore `canSubmitMafiaVote`/`pendingNight`'s mafia-pending count and `resolve-night.ts`'s `resolveMafiaTarget`) did not consult `ruleset.firstNightKill`, only `activeNightActionFor` did (used for non-mafia individual actions). So on night 1 with `firstNightKill: false`, mafia could still submit a kill vote and have it resolve — the gate was a no-op for the mafia consensus path. Fixed by making `mafiaKillers` return `[]` when `!state.ruleset.firstNightKill && state.day === 1`, which is the single choke point all mafia-kill logic already goes through.
- D7 additions: night-timer `setDeadline` at `startGame`; `firstNightKill=false` night-1 no-op with detective/angel still acting; `timerExpired` defaults (unsubmitted actions no-op, unvoted players abstain, nobody dies); `forceAdvance` mid-night defaults incl. mafia plurality-of-submitted; `markAbsent` on the sole pending actor triggers immediate zero-pending advance; dawn/dusk beat `setDeadline` effects using `dawnDuskBeatMs`; projection key-absence check for the pending-count field on living night views plus join-order assertions across night/dawn/day/resolved-vote phases and player/host/public viewer kinds.
